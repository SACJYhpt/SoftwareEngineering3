以完整 R2 後端的 API、模型、持久化寄信佇列、worker、權限與測試為準。組員分支也改了後端帳號流程，直接覆蓋會遺失個資同意、一次性 token、節流與完整 R2 功能，因此沒有保留第二套後端。

| 組員前端原差異 | 整合版 |
|---|---|
| 註冊讀取 `/units` | 改用公開 `/departments` |
| 註冊未帶個資同意 | 顯示 `/privacy-notice`；送出 `consent`、`privacy_version`；版本過期重新確認 |
| `/auth/password-reset/request`、`/confirm` | 使用 `/auth/forgot-password`、`/auth/reset-password` |
| 僅讀 query token | 優先讀信件的 fragment token，相容 query，取出後移除網址中的 token |
| 建立活動未處理主辦規範 | 收到規範錯誤後載入最新版，使用者確認後提交 acknowledgement 再建立 |

| 公開頁載入外部 QR 圖 | 改為本單位管理者授權下載後端 PNG |
| 過期憑證讓所有 GET 以訪客重試 | 僅真正公開的 GET 重試；私人 API 與 QR 不重試 |

沒有新增另一套登入、資料庫或服務架構。活動與報名核心不重寫。組員的 6 個後端測試保留情境並調整為目前正式契約。

## 最短啟動方式（Windows）

請在 **這份整合資料夾** 開兩個 PowerShell，不要一邊開舊資料夾的後端、一邊開新資料夾的前端。

第一個視窗，由根目錄執行：

```powershell
cd backend
$env:DATABASE_URL = 'sqlite:///./unified-demo.db'
powershell -NoProfile -ExecutionPolicy Bypass -File .\run.ps1 -SeedDemo
```

`run.ps1` 會安裝依賴、在沒有 `.env` 時產生隨機密鑰，建立示範資料並啟動後端。第一次使用尚不存在的資料庫檔名；舊資料庫不會自動升級，遇到舊結構請換新測試檔名，不要對團隊資料庫使用 `--reset`。

第二個視窗，由同一根目錄執行：

```powershell
cd frontend
npm ci
npm run dev
```

網頁開終端機顯示的 Local 網址（預設 `http://localhost:5173`）；後端文件為 `http://127.0.0.1:8000/docs`。若 8000 已有舊服務，先在原服務視窗按 Ctrl+C，避免連到舊版 API。前端轉送目標預設為 8000，可用 `VITE_BACKEND_URL` 明確指定。

本機示範帳號：`student1@demo.ntou.edu.tw`、`manager@demo.ntou.edu.tw`，密碼均為 `DemoOnly!2026`。這些帳號已驗證，適合先確認登入、搜尋、活動及報名。

新註冊帳號的驗證信／重設信，需要團隊設定 SMTP 並另開 worker（`backend/venv/Scripts/python.exe worker.py`）。未設定 SMTP 時只會排入資料庫及記錄寄送失敗，不會寄到真正信箱，也不會把私密連結顯示在公開 API。不要把團隊密鑰、`.env` 或測試資料庫提交到 GitHub。
