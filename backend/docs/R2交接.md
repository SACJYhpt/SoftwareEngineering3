## 先看這三件事

1. 不要拿舊 `demo.db` 直接啟動 R2。模型增加欄位，`create_all()` 不會升級既有表，啟動時會拒絕舊結構；原資料未被自動更動。
2. SMTP 尚未設定時，信件只會排入資料庫，worker 會留下失敗與重試紀錄，**不會假裝寄送成功**。
3. 前端已完成 R2 畫面（註冊、驗證、重設密碼、我的活動、活動管理、主辦規範、系統管理等），對照表見 `frontend/README.md`。

## 本機啟動：保留舊資料

在這份整合版的 `backend` 開 PowerShell。先安裝根目錄 README 的依賴；已有 Python 環境也可重用，但必須安裝新加入的 `qrcode[pil]`。

```powershell
python -m venv venv
venv\Scripts\python.exe -m pip install -r requirements.txt -r requirements-dev.txt
```

若沒有 `.env`，執行 `run.ps1` 會建立隨機 JWT_SECRET；建立後可停止再做初始化。不得使用 `.env.example` 的 replace-with 範例作為密鑰。
使用一個**尚不存在**的資料庫名稱，不用 --reset：

```powershell
$env:DATABASE_URL = 'sqlite:///./r2-demo.db'
venv\Scripts\python.exe init_data.py --demo
venv\Scripts\python.exe -m uvicorn main:app --host 127.0.0.1 --port 8000
```

CMD 對應設定為 `set "DATABASE_URL=sqlite:///./r2-demo.db"`，其餘 Python 指令相同。
`.env` 原設定不會被這個環境變數覆寫到檔案，設定只對目前視窗有效。
示範帳密仍是根目錄 README 的帳號，密碼 `DemoOnly!2026`。示範帳號明確標為已驗證；正式註冊預設未驗證。
示範 seed 只替模擬帳號建立規範確認，不能用來代替真實使用者同意。

`/docs`：http://127.0.0.1:8000/docs 。JWT 放進 Authorize，只貼 token，不額外加 Bearer。

## 前端 API 契約

所有需要登入的請求都帶 `Authorization: Bearer <access_token>`。登入與原有 MVP 的路徑／欄位保留。
R2 私人回應使用 `Cache-Control: no-store`。登出及重設密碼後的舊憑證均被拒絕。

### 公開帳號流程

| API | Request body／query | 回應 |
|---|---|---|
| GET /privacy-notice | 無 | id、kind、version、content、published_at；沒發布為 503 |
| POST /auth/register | 下方範例 | 201，verification_required=true；信件排佇列 |
| POST /auth/verify-email | `{ "token": "連結中的 token" }` | 200；過期／已使用／被新連結取代為 400 LINK_INVALID |
| POST /auth/resend-verification | `{ "email": "..." }` | 202，已註冊與未註冊同格式；60 秒內 429，附 retry_after_seconds |
| POST /auth/forgot-password | `{ "email": "..." }` | 202，同格式不透露帳號是否存在；60 秒頻率限制 |
| POST /auth/reset-password | `{ "token": "...", "password": "NewPassword123" }` | 200；1 小時到期及單次使用 |
| GET /departments | 無 | 只有啟用中的系所 id、name |

```json
{
  "email": "student@mail.ntou.edu.tw",
  "password": "NewPassword123",
  "name": "測試學生",
  "identity": "student",
  "department_id": 1,
  "grade": 1,
  "consent": true,
  "privacy_version": 1
}
```

identity 為 student／teacher／staff；學生必填 grade。版本須先從 /privacy-notice 取得，不要硬編碼 1。
密碼至少 8 碼且含英文字母與數字；註冊不可指定 role、驗證狀態或其他額外欄位。
未驗證帳號且帳密正確登入回 403 EMAIL_NOT_VERIFIED；帳密錯誤仍是統一 401。

信中的連結是 `PUBLIC_BASE_URL/verify-email#token=...` 或 `/reset-password#token=...`。
前端新增對應頁面，讀取 fragment 後 POST token，使用後從網址移除。token 不放 query，避免出現在伺服器存取日誌。
前端的 `/verify-email`、`/reset-password` 頁面會讀取 `#token`、送出後自動從網址移除。

### 探索、個人活動與主辦規範

| API | 行為 |
|---|---|
| GET /events?q=參訪&type=參訪&date_from=2030-01-01&date_to=2030-01-31&limit=30&offset=0 | AND 組合、台灣日期起迄日均納入，依開始時間排序；分頁 (limit 1–100，預設 30)，符合總數在 `X-Total-Count` 標頭；每筆只含卡片欄位 (EventSummary)，完整內容用 GET /events/{id} |
| GET /faq | 公開 content、version、published_at；前端顯示更新時間 |
| GET /organizer-terms | 最新主辦規範，與個資告知分開 |
| POST /organizer-terms/acknowledgements | body `{ "document_id": 2 }`，需要登入；舊版 409 DOCUMENT_OUTDATED |
| GET /me/events | 本人正式報名、尚未結束且未取消的活動；含 registration_id、registered_at、can_cancel_registration |
| GET /me/events/history | 本人已結束且未取消的參加紀錄；attendance_status="未記錄" |
| DELETE /events/{id}/registrations/me | 無 body；截止前取消，成功回 status="cancelled"、registration_count、capacity 等 |

取消後紀錄保留 status=cancelled、cancelled_at，詳情顯示「已取消」；重新報名重用同一筆紀錄，正式人數只計 registered。
重複取消回 404 REGISTRATION_NOT_FOUND，不再扣人數。前端二次確認按「取消」時不要發 API。

SRD 0.5 起 C03 改為嚴格比較：活動結束須晚於開始、報名開始須早於報名截止，相等也會被拒絕 (422)；報名截止仍可等於活動開始。
前端表單使用相同規則。

### 活動管理：每次請求查單位授權，不看 owner_id

| API | Request／回應 |
|---|---|
| GET /manage/events | 自己所屬單位的活動，含同單位其他人建立的活動 |
| GET /events/{id}/registrations | event_id、registration_count、registrations；名單依報名時間／id 排序 |
| GET /events/{id}/qr | PNG 下載，只含公開活動固定連結，不含 token 或個資 |
| PATCH /events/{id} | 僅傳修改欄位，與建立欄位同名；不可改 unit_id、owner_id |
| POST /events/{id}/cancel | `{ "reason": "颱風取消" }`，前端須先二次確認 |

PATCH 可修改 name、type、description、location、contact_information、start_time、end_time、registration_start、registration_deadline、capacity、notes。
capacity 或 notes 明確傳 null 表示不限／清除；其他必填欄位不得 null。
未取消且未結束才可修改；已進行中時允許改地點等資訊，但不能把新的開始時間改到過去。
異動將原值／新值與通知信一起寫入資料庫，交易失敗不留下假通知；SMTP 失敗不讓活動修改失敗。
停用單位無法建立新活動，但仍可管理既有活動。停用類型不影響既有活動顯示。
管理者和系統管理員都能以一般使用者身分報名；管理活動仍依單位授權，admin 不自動取得所有活動管理權。

### 系統管理：以下皆須 role=admin

| API | body／用途 |
|---|---|
| GET /admin/users?q=王&unit_id=1&role=manager&page=1&page_size=20 | 分頁搜尋／篩選，page_size 上限 100；每筆含目前管理的單位 (managed_units)；不回傳雜湊、年級等非必要資料 |
| PUT／DELETE /admin/units/{unit_id}/managers/{user_id} | 指派／取消該單位資格，無 body；不允許對 admin 帳號變更 |
| GET／POST /admin/units | 查全部（含停用）／新增 `{ "name":"資工系", "kind":"department", "is_active":true }` |
| PUT／DELETE /admin/units/{id} | 完整更新／刪除；已被活動、使用者或管理資格引用不可刪 |
| GET／POST /admin/event-types | 查全部／新增 `{ "name":"參訪", "is_active":true }` |
| PUT／DELETE /admin/event-types/{id} | 完整更新／刪除；已使用類型只能停用，改名同步既有活動 |
| POST /admin/documents/{privacy\|organizer\|faq} | `{ "content":"內容" }`，產生新版本並保留舊版 |
| GET /admin/emails?status=failed&page=1&page_size=20 | 信件狀態與失敗紀錄，不回傳內含 token 的郵件 body |
| POST /admin/emails/{id}/retry | 只接受 failed，回 202；新一輪寄送仍保留過往嘗試紀錄 |
| GET /admin/backups | 最近 7 天備份狀態、時間、檔名與錯誤類型 |

單位 kind 為 department／office／club。類型／單位維護用 PUT，前端須送完整名稱與狀態。
角色 manager/member 會隨剩餘單位授權調整；登入憑證不內嵌單位權限，既有登入下一次請求就生效。
沒有建立指派系統管理員、稽核查詢、資料庫下載或 HTTP 還原接口。

## SMTP 與背景 worker

在自己的 `.env` 設定 SCHOOL_EMAIL_DOMAINS、PUBLIC_BASE_URL、SMTP_HOST、SMTP_PORT、SMTP_SECURITY、SMTP_USER、SMTP_PASSWORD、MAIL_FROM。
學校網域預設 ntou.edu.tw 及其子網域，可用逗號設定多個允許網域；不接受 ntou.edu.tw.attacker.com。
SMTP_SECURITY 為 starttls（預設）、ssl 或 none（供本機測試）。密鑰不可 commit。
API、worker 必須使用同一個 DATABASE_URL；另開視窗啟動：

```powershell
$env:DATABASE_URL = 'sqlite:///./r2-demo.db'
venv\Scripts\python.exe worker.py
```

`worker.py --once` 處理一批後離開。初次失敗後等 60、120、240 秒重試（共 4 次嘗試），仍失敗標為 failed；管理員可手動排入新一輪。
每次失敗／成功都有獨立 EmailAttempt，錯誤不記錄可能含密鑰的完整例外。
worker 異常退出後有 5 分鐘租約回收。SMTP 不保證 exactly-once，寄出後、寫回狀態前崩潰可能重寄。

## 每日備份及還原 SOP

在 worker 環境明確設定 `BACKUP_ENABLED=1`，BACKUP_DIR 指向只有維運人員可讀的目錄。
常駐 worker 每 5 秒檢查佇列，依台灣日期每日備份一次；部署時由維運負責人將 worker 設為常駐服務。
`worker.py --backup-now` 可在 CLI 執行一次備份。檔案超過 7 天會清除，只清除備份目錄內的受管檔名。
備份含個資、密碼雜湊和郵件連結，不可放進 public、Git 或公開下載位置。

- SQLite：使用 sqlite3 backup API，而非在寫入中直接複製檔案。
- MySQL：需在執行 worker 的環境提供 MySQL 8.x 的 mysqldump 與 mysql；使用單一交易 dump。帳密放入暫存 option file，不放 argv 或日誌。
- 失敗：保留 BackupRecord，將通知排給所有啟用中的系統管理員；SMTP 尚未設定時通知也不會實際送達。
- 專用測試環境還原：先停止目標服務，建立**不同於現用資料庫**的空目標。SQLite 目標檔必須不存在，MySQL 目標 schema 必須無資料表。

```powershell
$env:RESTORE_DATABASE_URL = 'sqlite:///C:/private-restore-test/restored.db'
venv\Scripts\python.exe worker.py --restore 'C:/private-backups/events-實際檔名.sqlite' --confirm-empty-target
```

MySQL 的 RESTORE_DATABASE_URL 改成專用空測試庫。程式拒絕還原到現用或非空資料庫。
先核對表數、帳號／活動／有效報名人數、外鍵及抽樣資料，再由維運人員安排正式切換；本次沒有執行團隊資料庫還原。

## 資料庫負責人需要處理什麼

`schema-r2.sql` 是從目前 models 產生的**全新 MySQL 資料庫 DDL 參考**，不是升級腳本，不可直接覆蓋既有資料庫。
`create_all()`／init_data.py 不會升級舊欄位；本次沒有導入 migration framework 或更改團隊資料。

既有表變更：

- users：email_verified（新帳號預設 false）、token_version、consent_at、privacy_version。
- units：is_active。
- events：cancellation_reason；時間限制為 ends_at > starts_at、registration_opens_at < registration_closes_at、registration_closes_at <= starts_at (SQLite 既有測試資料庫的舊限制較寬，但 API 仍會擋下相等的時間)。
- registrations：status（registered／cancelled）、cancelled_at；維持同人同活動唯一，重新報名重用該筆。

新增表：published_documents、organizer_acknowledgements、account_tokens、account_requests、outgoing_emails、email_attempts、backup_records。
資料庫負責人需備份後安排 ALTER、既有狀態回填及外鍵／索引驗證。已知 MVP seed 帳號可回填已驗證，但不能把未知真實帳號一律標為已驗證。
既有有效報名回填 registered；新文件的確認不得替真實使用者代勾。

## 文件內容與正式驗收界線

development 初始化會建立明確標示的個資告知、主辦規範草案及 FAQ，供本機串接；production 不自動發布草案。
正式環境由管理員發布團隊核定的內容。法規、保存期限與告知內容仍須團隊查證；目前沒有自動個資去識別化，不能寫成「已實作到期刪除」。
未發布必要文件時註冊／建立活動回 503，不會跳過同意流程。

自動測試在 tests/test_r2.py、tests/test_operations.py，並保留原 MVP、報名及單位權限測試。
完整回歸結果為 **155 passed, 1 skipped, 1 warning**；最後 SQLite 連線釋放調整後，維運 7 項測試及實際 HTTP／worker／備份還原流程另行通過。
測試使用獨立 SQLite；SMTP 有本機協定收信測試和故障重試模擬，不使用外部信箱。
MySQL 併發測試需 MYSQL_TEST_URL，沒有設定會 skipped，不代表正式 MySQL 已驗收。
本機 1000 活動／50 個並行 HTTP 搜尋請求曾量得 50/50 成功、p95 2.852 秒；只代表該次本機 SQLite API 量測，不等於校園網路頁面載入或正式 MySQL 壓測。
測試負責人可在 backend 執行 `venv\Scripts\python.exe tests/benchmark_r2.py` 重跑；使用臨時資料庫，不會修改現有資料。
正式 SMTP 投遞、MySQL 備份還原、常駐排程、HTTPS、跨瀏覽器及 UI 驗收由團隊環境確認。
